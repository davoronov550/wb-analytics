# Миграция на FastAPI и микросервисную архитектуру

Перевод сервиса аналитики товаров Wildberries с Django + модульный монолит на
FastAPI + микросервисы, с технологическим стеком highload-сегмента.

**Скоуп — миграция без изменения функциональности.** Новые продуктовые
возможности из скоупа исключены; продукт после миграции делает ровно то же,
что делает сейчас.

## Резюме

**Гексагональная архитектура текущего проекта не декоративная, и это главный
дивиденд.** `domain/` и `application/` (~1 800 строк) не импортируют ни Django,
ни DRF, ни Celery — проверяется 149 тестами, работающими без инфраструктуры.
Эти слои переносятся в FastAPI **копированием без правок**, вместе с тестами.
Переписывается только содержимое `adapters/` и `composition/`. Это сокращает
объём работы примерно вдвое против миграции с типичного Django-проекта.

**Три блокера распила**, все локальные и снимаемые за одну фазу:

- `analytics` импортирует ORM-модель `catalog` напрямую — общая БД между
  контекстами;
- `scheduling` вызывает composition root `catalog` внутрипроцессно;
- шина событий синхронная, а её «брокерный» режим оказался заглушкой на
  `logger.info`.

**Настоящая опасность — не смена фреймворка, а два места, где ошибка
необратима:** бэкфилл истории цен в ClickHouse (Wildberries прошлых цен не
отдаёт) и тихая потеря поведения при переписывании адаптеров. Оба закрываются
процедурой: двойная запись со сверкой и чек-лист паритета как приёмочный
документ.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Скоуп | **Только миграция.** Новые функции исключены — [док. 2, §2.4](02-functional-parity.md) |
| Гранулярность | **9 независимых сервисов**: gateway, identity, ingestion, catalog, timeseries, analytics, scheduling, notifications, export |
| Хранилище рядов и агрегатов | **ClickHouse** — `ReplacingMergeTree`, партиции по месяцам, TTL 24 мес |
| Событийная шина | **Apache Kafka 4.x (KRaft)** + Schema Registry + transactional outbox, четыре топика |
| Синхронный обмен | **gRPC** между сервисами (один Protobuf-IDL с событиями), **REST** только на внешнем периметре |
| HTTP-клиент | **aiohttp** — async-native; попутно даёт ротацию прокси на каждый запрос, чего `httpx` не позволял |
| Пагинация | **Серверная**, keyset. Сейчас она клиентская, из-за чего выборка за пределами 1000 строк недостижима |
| Мультиарендность | **Не вводится.** Без организаций «арендатор» совпал бы с пользователем — [док. 3, §3.1](03-target-architecture.md) |
| SSO / Keycloak | **Не вводится.** Собственный `identity-service` — Keycloak нужен был ради SAML и SCIM, которых нет в скоупе |

Следствие решения о девяти сервисах: `libs/platform`, шаблон сервиса,
Helm-каркас и ArgoCD нужны **с фазы 0-1**, а не в конце; контрактные тесты
`pact` становятся обязательными.

## Три допустимых отклонения от паритета

Не расширение функциональности, а следствие требований highload. Пользователь
видит то же самое; меняется устройство.

1. **Гистограммы переезжают на сервер.** Сейчас считаются на клиенте из списка
   товаров — ровно поэтому `PAGE_SIZE = 1000`. Keyset-пагинация это ломает.
   Побочный эффект: графики станут **точнее**, потому что начнут строиться по
   всей выборке, а не по первой тысяче строк.
2. **Экспорт становится асинхронным.** XLSX сейчас собирается в памяти
   процесса; на больших выборках это кладёт процесс и упирается в таймаут
   балансировщика.
3. **Появляется задержка согласованности 1-5 с** после сбора. Закрывается
   прогрессом по WebSocket с явными стадиями.

## Сроки

**11-16 недель** для команды 3-4 инженеров с опытом FastAPI, Kafka и
Kubernetes. Без опыта Kafka и ClickHouse — плюс 3-4 недели.

Около 3 недель из этого срока приходятся на CI/CD и эксплуатационную обвязку
девяти отдельных деплой-юнитов.

## Что нельзя сокращать

- **Фазу 0.** Без замороженного OpenAPI-контракта миграция неуправляема.
- **Transactional outbox.** Без него потеря событий — вопрос времени, а не
  вероятности.
- **`libs/platform` и шаблон сервиса.** На девяти сервисах дублирование
  инфраструктурного кода неуправляемо.
- **Двойную запись со сверкой в фазе 3.** Единственный способ убедиться, что
  бэкфилл не потерял историю.
