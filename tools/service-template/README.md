# Шаблон сервиса

Каркас нового сервиса: гексагон, обвязка `libs/platform`, Dockerfile,
helm-values и тесты, включая проверку слоистости.

```bash
uv run cookiecutter tools/service-template --output-dir services
uv sync --all-packages
uv run pytest services/<name> -q
```

## Зачем шаблон

Девять сервисов, собранных вручную, разойдутся: девятый будет отличаться от
первого тем, что за это время выяснилось про пробы, ресурсы или обработку
ошибок. Шаблон — это способ применить выясненное сразу ко всем.

Он же переносит в новый сервис три вещи, которые легко забыть по одному разу
на сервис и дорого обнаружить в проде:

- логи и трассировка настраиваются **до** всего остального, поэтому падение при
  старте всё ещё структурировано и всё ещё несёт `trace_id`;
- один обработчик исключений — ни один маршрут не может ответить без конверта
  или раскрыть внутреннее сообщение;
- `/healthz` не трогает зависимости: Kubernetes **перезапускает** контейнер, не
  прошедший liveness, а перезапуск не чинит базу.

## Проверка слоистости

`tests/test_layering.py` разбирает AST и запрещает `domain/` и `application/`
импортировать фреймворки, драйверы и адаптеры. Именно это свойство позволило
перенести ~1 800 строк из Django копированием, и оно стоит ровно столько,
сколько стоит его проверка.

Слои размываются по одному удобному импорту за раз, и каждый выглядит
безобидным.

## Переменные

| Переменная | Смысл |
|---|---|
| `service_name` | Имя сервиса и каталога: `catalog`, `analytics` |
| `package_name` | Python-пакет, выводится из имени |
| `http_port` / `grpc_port` | Порты |
| `has_database` | PostgreSQL и Alembic |
| `has_kafka` | Продюсер, консьюмер, Redis для дедупа |
| `has_grpc` | Серверные и клиентские интерцепторы |

`has_*` управляют не только зависимостями, но и составом файлов: сервис без
базы не получает `alembic/`. Неиспользуемый каркас хуже отсутствующего — в
пустой `alembic/` рано или поздно напишут миграцию, которую никто не выполняет.

## Контекст сборки образа

Корень репозитория, а не каталог сервиса:

```bash
docker build -f services/<name>/Dockerfile -t wb-<name> .
```

Сервис зависит от `wb-platform` из `libs/platform` и от корневого `uv.lock`.
Контекст, ограниченный каталогом сервиса, не видит ни того, ни другого, и
сборка падает так, будто дело в зависимостях.
