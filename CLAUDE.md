# Правила работы с проектом

Обязательны к соблюдению. Каждое правило здесь появилось из конкретной ошибки —
источник указан, чтобы правило не выглядело произвольным и не было отменено
«для скорости».

Контекст миграции: [docs/migration/00-overview.md](docs/migration/00-overview.md).
Текущая задача и статусы: [док. 8](docs/migration/08-tasks.md).

---

## 1. Документация до кода

**Перед тем как писать код, использующий библиотеку, обратиться к её
документации через Context7 MCP** (`resolve-library-id` → `query-docs`).
Не по памяти. Не «я это знаю».

Правило введено после серии ошибок, каждая из которых прошла бы ревью и дала
бы **молча неверный результат**, а не отказ:

| Что я утверждал | Что оказалось на самом деле |
|---|---|
| `quantileExact(0.5)` заменяет `PERCENTILE_CONT` | Возвращает существующий элемент, а PostgreSQL интерполирует: 2868 против 2866. Верен `quantileExactInclusive`, и он **не принимает `Decimal`** |
| `topK(5)` даёт топ-5 по отзывам | Возвращает самые **частые** значения: `[179, 483, 653, 670, 8]` вместо `[892, 891, 890, 889, 888]` |
| `histogram(10)` строит гистограмму как на фронтенде | Корзины **адаптивные**, разной ширины; фронтенд равноширинный. Нужен `widthBucket` |
| «Taskiq поверх Kafka» | Официальных Kafka-брокеров у Taskiq нет |
| Настройки топиков Kafka кодом не проверяются | `describe_topics` и `describe_configs` читают их из брокера |

Отдельно: **умолчания библиотек чаще небезопасны, чем безопасны.** У
`aiokafka 0.14` — `enable_auto_commit=True`, `enable_idempotence=False`,
`auto_offset_reset='latest'`. Последнее означает, что новая консьюмер-группа
пропускает всё накопленное в топике.

**Следствие для кода:** небезопасные умолчания не документируются, а
закрываются фабриками (`producer_config()`, `consumer_config()`) — сервис не
должен иметь возможности получить опасную конфигурацию по невнимательности.

## 2. Проверять эмпирически, а не рассуждением

Где есть поднятая инфраструктура — проверять на ней, а не полагаться на
логику. Так были найдены:

- расхождение медианы PostgreSQL и ClickHouse (2866 против 2868);
- `min.insync.replicas=1` на dev-брокере, обесценивающий `acks=all`;
- `localhost` в healthcheck: сервисы слушают `0.0.0.0` (только IPv4), а
  `localhost` внутри контейнера резолвится в `::1` — проверка получала
  connection refused при полностью рабочем сервисе;
- psql не подставляет переменные внутри dollar-quoted блоков, поэтому
  `DO $$ ... :'var' $$` отправил бы на сервер литерал.

`docker compose config` и зелёные тесты обе сломанные версии считали
корректными.

```bash
./tools/dev-up.sh          # поднять окружение
./tools/dev-up.sh --reset  # пересоздать тома после правки init/*
```

## 3. Определение готовности задачи

Задача закрыта, когда выполнено **всё**:

1. `ruff check` и `mypy --strict` проходят.
2. Тесты написаны **до** реализации; покрытие модуля ≥ 80 %.
3. CI зелёный целиком.
4. Если задача трогает контракт — `contracts/` обновлены, `schemathesis` или
   `buf breaking` проходят.
5. **Статус в [док. 8](docs/migration/08-tasks.md) переведён в «готово» в том
   же коммите.** Затронуты решения из документов 1-6 — обновить там же.

Пункт 5 добавлен после того, как первые семь задач были закрыты в коде, но
остались отмечены как не начатые. План, расходящийся с репозиторием, хуже
отсутствующего: ему верят.

```bash
uv run ruff check . && uv run mypy
uv run pytest libs -q -m "not integration"     # офлайн
uv run pytest libs -q                          # с инфраструктурой
uv run python tools/task-graph.py              # перегенерировать граф
```

## 4. Тесты проверяют дефект, а не покрытие

Зелёный тест — не доказательство. Для нетривиальной логики убедиться, что тест
**падает** на сломанной реализации.

Так проверен property-тест keyset-пагинации: цепочка условий заменена наивным
сравнением по первому уровню, тест упал и сузил контрпример до трёх строк с
равным `rating` и страницей в одну строку.

Named test suites, фиксирующие найденный дефект как регрессию:
`TestNoSilentLoss` в `test_kafka.py`.

## 5. Порядок задач задаёт граф, а не номера

Номер — идентификатор. Порядок определяют колонка «Зависит» и критический путь
из [док. 7, §7.4](docs/migration/07-implementation-plan.md). Задачи с меткой
`[P]` откладываются сознательно.

**Отступление от номерного порядка — норма. Ненормально не объявить его:**
раздел «Прогресс» в док. 8 обязан отвечать «что сделано и что следующее» без
чтения истории коммитов.

## 6. Домен переносится копированием

`domain/` и `application/` (~1 800 строк) не импортируют ни Django, ни DRF, ни
Celery. Они переносятся **копированием вместе с тестами**, не переписыванием.

В них спрятаны неочевидные решения: `Rating.coerce` и `ReviewsCount.coerce` —
лечение конкретной грязи в данных Wildberries, `Money.from_kopecks` — формат
цены площадки, политика повторов в шлюзе — результат опыта. «Перепишем
красиво» возвращает уже вылеченные баги.

**Правка в `domain/` или `application/` — стоп-сигнал, а не прогресс.**
Единственное санкционированное исключение — `Ordering` (многоуровневая
сортировка, [док. 7, §7.6](docs/migration/07-implementation-plan.md)).

## 7. Что принадлежит `libs/platform`

Код попадает туда, когда появляется во **втором** сервисе копипастой — не
раньше (спекулятивная абстракция) и не позже (дублирование по девяти
деплой-юнитам). Доменная логика конкретного сервиса туда **не переезжает**.

## 8. Контракт API заморожен

Единственные допустимые отклонения — четыре, перечисленные в
[док. 2, §2.3](docs/migration/02-functional-parity.md): серверная пагинация и
сортировка, асинхронный экспорт, задержка согласованности, конверт ошибок.
Любое другое расхождение с `contracts/openapi/v1.yaml` — красный CI.

[Док. 2](docs/migration/02-functional-parity.md) — приёмочный документ, а не
справочный: миграция завершена, когда отмечены все 33 строки чек-листа.

## 9. Стиль

**Код и docstring — по-английски**, как в существующем `backend/src`.
**Документация, комментарии в конфигурации и сообщения коммитов — по-русски.**

Комментарий объясняет **почему**, а не что. «Что» видно из кода.

Коммиты: `<type>: <описание>`, типы `feat|fix|refactor|docs|test|chore|perf|ci`.
Атрибуция отключена глобально — не добавлять.

## 10. Ветка

```
main                                  ← продакшн
  └── migration/fastapi-microservices ← длинная ветка миграции
```

Живёт до конца фазы 5, вливается после вывода Django из контура. `main`
вливается в неё не реже раза в неделю.

## 11. Признавать ошибку, а не защищать формулировку

Дважды в этом проекте удобная формулировка скрывала дефект:

- «известное ограничение» дедупа в Kafka на деле означало, что сообщение
  доставлено и никогда не обработано;
- «настройки топиков кодом не проверяются» — неверное утверждение, которым
  была отложена вторая половина гарантии `acks=all`.

Оба нашлись вопросом на ревью, а не тестом. При сомнении — проверять, а не
обосновывать.

## Принятые решения

Не пересматривать без явного обсуждения.

| Вопрос | Решение |
|---|---|
| Скоуп | Только миграция, без новых продуктовых функций |
| Гранулярность | 9 независимых сервисов |
| Хранилище рядов | ClickHouse |
| Событийная шина | Kafka 4.x (KRaft) + Schema Registry + transactional outbox |
| Синхронный обмен | gRPC между сервисами, REST только на периметре |
| HTTP-клиент | `aiohttp` (прокси ротируется на каждый запрос; `httpx` этого не даёт) |
| Очередь задач | **Не вводится** — фоновая работа на Kafka-консьюмерах |
| Мультиарендность | Не вводится |
| SSO / Keycloak | Не вводится, собственный `identity-service` |
